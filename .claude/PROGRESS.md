## Known gotchas from recent sessions
- **`/api/check-duplicate-covers` has NO access control — this is a real, currently-exploitable gap, not a hypothetical one.** Anyone who finds the endpoint can enumerate draft-catalogue GI Item/Date pairs with zero credentials, since there's no auth anywhere in this app yet. Must get real access control (most likely tied to T-04's Admin auth) before this goes anywhere past local development. Do not let this quietly become "fine because nobody's found it."
- **This Supabase project is missing standard default privileges for `service_role`** — see the T-03 writeup above. If a *new* table ever hits the same `42501 permission denied` error for `service_role` despite the `ALTER DEFAULT PRIVILEGES` fix, check whether that table was created before the fix migration ran, or via a path that bypasses default privileges.
- **Service-role key leak guardrail added.** `scripts/check-no-secret-leak.mjs` (via `npm run check:secrets`, chained into `npm run build`) greps git-tracked files and the built client bundle (`.next/static`) for the `sb_secret_` key pattern and fails the build if found. Defense-in-depth alongside Next.js's own `NEXT_PUBLIC_`-only client exposure and the `server-only` import guard in `supabaseAdminClient.ts`. Verified it actually catches a leak (staged a fake key, confirmed non-zero exit, then cleaned up) — not just that it passes on clean input. **Not yet wired into an actual CI pipeline** — no GitHub Actions workflow exists yet in this repo (that's Session 7 per `docs/AI-Agent-Implementation-Brief.md`); until then this only protects local builds, not PRs from other sources.
- **T-05 must call the shared CSV sanitizer — do not skip it or reimplement it.** Lives in `src/lib/sanitizeCsvCell.ts`, applied to every column via Papa Parse's `transform` option (not just the image filename). The T-02 UI check is convenience only, not a security boundary (per the Security/Trust-Boundary design) — T-05's actual insert path (the bulk-import Edge Function) must apply this exact same sanitization before persisting any CSV-derived value. The Edge Function runs on Deno, a different runtime than this Next.js app — if a direct import isn't practical there, T-05 must still use logic identical to it, not a separately-invented sanitizer. Regression-protected by `src/lib/sanitizeCsvCell.test.ts` — extend that file rather than re-verifying by hand if the logic ever changes.
- **T-05 must real-world-test date parsing before calling it done.** The T-02 fixture had dates normalized to clean ISO format, so it never exercised the actual source spreadsheet's mixed date formats (e.g. "05.09.2021"). T-05's `date_of_issue` parsing needs a real test against messy rows pulled directly from `PhilaIndiaCovers-PLabs.xlsx`, not just clean fixtures.
